# Deep Dive: Human-in-the-Loop (HITL) Patterns

"Human-in-the-Loop" does not just mean putting an "Approve" button at the very end of a 20-minute agent execution. Effective supervision happens before, during, and after a run.

## 1. A Priori Control (Before the run)
The most important human control happens before the agent even starts. This includes:
- Defining the **Work Orders** and **Role Specifications**.
- Setting the **Budgets** (e.g., maximum token spend, maximum API calls).
- Defining the **Tenant Boundaries** (which data the agent is legally allowed to touch).

## 2. Co-Planning (During the run)
When an agent receives a complex objective, it should generate an Execution Plan and immediately pause.

A human reviews the graph of tasks the agent intends to execute. The human can correct the priority, add missing context, or delete dangerous steps *before* the agent burns compute or causes damage.

## 3. Runtime Monitoring (During the run)
While the agents are executing the approved plan, humans do not need to approve every single tool call. Instead, they rely on **Event/Status Views**.

The system emits standard telemetry (OTel traces) showing which agent is working, which tool it is calling, and its current spend. If the human sees the agent stuck in a loop, they trigger a manual "Kill Switch."

## 4. The Review Queue (After the run)
When the agents have synthesized a final proposal (e.g., a code patch, a customer refund), execution pauses again.

The system places the proposal in a **Review Queue**. The human approver does not just see the final answer; they see the *Evidence*. They see the cryptographic signatures of the tools used, the intermediate artifacts generated by the specialists, and the dissent (if any) from the Adversarial Reviewer agent.

The human then signs off with their own cryptographic identity, executing the final, consequential action.
